# 安全与合规审查（2026-10-29）

> 审查对象：`server/`、`src/agents/`、`src/ui/`、部署包 `deploy/app/`。
> 结论先行：**没有发现高危问题**；有 4 项需要在文档与产品文案里说清的残余风险。

## 一、逐项结论

| 面 | 检查 | 结论 |
|---|---|---|
| XSS | 是否使用 `innerHTML` / `dangerouslySetInnerHTML` | **无**。模型输出经 `domain/markup.ts` 解析成结构化片段，由 React 渲染；标签一律当文本 |
| 提示注入 | 玩家输入是否与指令隔离 | 行动包在 `<<< >>>` 中并声明"是剧情数据不是指令"；`sanitizeUserText` 去控制/零宽字符并截断。无工具执行，注入最坏是"剧情跑偏"，不是 RCE |
| 密钥 | 是否落盘 / 入日志 | 服务端不存用户 Key；日志只记 route/chars/ms/status；`.env` 被 `.gitignore` 忽略，部署包 `deploy/app/` **不含 `.env`** |
| SSRF | 前端能否指定任意上游地址 | 只能 `https`，且域名在 `api.deepseek.com` / `dashscope*.aliyuncs.com` / `api.openai.com` 白名单（可用 `LLM_ALLOWED_HOSTS` 追加）。实测 `http://127.0.0.1:8080` 返回 400 |
| 路径穿越 | 静态文件服务 | `normalize` + `startsWith(dist)` 双重校验，越界 403 |
| 滥用 | 限流与额度 | 令牌桶（叙事 8 rpm / 结构化 20 rpm）、并发 2、每日 100 万字符、body ≤1MB、正文 ≤6000 字、输出上限 |
| 数据驻留 | 故事存在哪 | 只在浏览器 IndexedDB；服务端只做转发，不写库、不落盘 |
| 依赖 | 运行时依赖 | 部署包只依赖 `yaml`；前端产物已构建，无第三方脚本 CDN |

## 二、残余风险（已写进产品文案，不假装不存在）

1. **本地 Key 与 XSS 同生共死**：Key 存 `localStorage`。当前没有 XSS 面，但一旦将来引入富文本 HTML，Key 就会被读走。约束：**永不接受 HTML**，这条写进 SPEC。
2. **共享设备**：Key 存在浏览器里，同一台机器的下一个人可能复用。设置页提供"清除本机 Key"，文档建议公共电脑用完清掉。
3. **内容合规**：没有内容审核。模型输出由上游供应商的策略兜底，本产品不做二次过滤；用户对生成内容负责。不面向未成年人做专门设计。
4. **存档含秘密**：导出 JSON 里有 `secrets` 与未揭开的隐藏项，**不能当公开文件分享**。导出页已就此加提示。

## 五、2026-10-29 复审：多模态、隐私声明与体验期内置 Key

### 5.1 新增的两类出站请求

| 入口 | 打到哪 | 谁决定 | 护栏 |
|---|---|---|---|
| `/api/image` | `images/generations`、百炼 `multimodal-generation` / 异步任务 | `resolveMediaTarget`（地址与 Key **成对**取） | https + 域名白名单；prompt ≤600 字；90–120s 超时；结果转 `data:` 存本地 |
| `/api/tts` | `audio/speech`、百炼 `SpeechSynthesizer` | 同上 | 文本 ≤900 字；60–90s 超时 |

**不跨对拼接**是这一版的关键决定：绝不允许出现「站点的图床 + 用户的 Key」或
「用户的地址 + 站点的 Key」。前者会 401 并让用户背锅，后者等于把站点的 Key 发给第三方域名。

**白名单放宽到 `*.aliyuncs.com` 后缀**：百炼业务空间域名形如
`{WorkspaceId}.cn-beijing.maas.aliyuncs.com`，主机名不固定，逐条列举不可维护。
放行范围仍限于阿里云自有域名，不是任意域名——SSRF 面没有实质扩大（`127.0.0.1`、内网域仍被拒）。

### 5.2 本地保存声明（用户可见）

隐私承诺写在**界面上**，不只写在文档里：书架底部常驻一行，设置页「数据与隐私」逐条列出。

- 世界 / 人物 / 正文 / 伏笔 / 生成图：IndexedDB，**不上传、不云同步、无账号**；
- Key：`localStorage`，随请求头转发，服务端不落盘、不写日志；
- 会出站的只有：写作上下文（含正文片段）与生图提示词 → 用户自己配置的模型供应商。

**这不是"零数据出站"**：生成内容必然要把上下文发给模型。说清楚比含糊承诺更可信。

### 5.3 体验期内置 Key（已按用户决定执行）

产品处于体验期、使用者少，因此线上实例**内置一把站点 Key**（`deploy/app/secrets.json`，
非 dotfile，避免被部署平台剔除）。这意味着：

| 风险 | 现状 | 缓解 |
|---|---|---|
| 链接被转发后额度被人用 | 存在 | `DAILY_CHAR_BUDGET=200000`（约一局半）、8 rpm/IP、并发 2 |
| Key 泄露后无法撤回 | 存在 | 只放体验用 Key，随时可在控制台撤销并替换 `secrets.json` 重新发布 |
| 站点 Key 被用于生图 | **不会** | 出图/语音只在站点显式配置 `media.*.baseUrl` 时才用站点 Key；当前未配置，BYOK 用户仍走自己的 Key |

**切换回纯 BYOK**：删掉 `deploy/app/secrets.json` 里 `LLM_API_KEY` 一行并重新发布即可，
前端会退回「去设置填一个 Key」的引导，无需改代码。

### 5.4 代码层复核

- 无 `innerHTML` / `dangerouslySetInnerHTML`；生成图只经 `<img src="data:...">`，不注入 HTML。
- 新增的模态框（人物库选择器）用 `role="dialog"` + Esc 关闭，不做焦点陷阱但也不锁滚动。
- 所有新接口都过 `preflight`（限流）与 `checkToken`（可选口令）；`/api/ping` 不计额度。
- 错误信息只含错误码与中文提示，不含上游原始响应体（截断 160 字后仅用于日志）。

## 六、2026-10-29 发布前复审（第二轮）

### 6.1 白屏事故的复盘

**现象**：点进 `#/library` 整页白屏，控制台只有压缩后的栈（`et → Bl → useState → renderWithHooks`），
看不出是哪个组件、哪个字段。

**根因**：早期原型索引条目没有 `tags` 字段，页面按 `p.tags.length` 渲染 → `undefined.length`。
同类风险还有 `personality / abilities / secrets`——都是"后来才加的字段"。

**修法**（两层，缺一不可）：

1. **仓储出口归一化**：`listPersonas / loadPersona` 读出来就补齐数组，且**不写回库**（避免每次读都触发写）。
   这与 `loadMeta / loadCanon` 用的是同一条规矩：字段补齐只在一处做。
2. **渲染兜底**：`ErrorBoundary` 包住路由区。以后再漏，也只是一页报错，不会整站白屏。
   兜底页只显示 `错误名: 消息` 与三个按钮，**不回显用户数据**，不构成新的信息泄露面。

**还有一条教训**：压缩后的栈对排障几乎无用。所以兜底页提供「复制错误信息」，
把完整 `message + stack` 给到开发者——这比让用户描述"点了一下就白了"有效得多。

### 6.2 多模态链路的复核结论

| 项 | 结论 |
|---|---|
| 地址收敛 | `compatible-mode/v1`、`api/v1`、业务空间域名三种写法都收敛正确；业务空间域名**不会被改写** |
| 协议判定 | `*.aliyuncs.com` 一律按百炼处理（业务空间域名不含 `dashscope` 字样，只认字面量会误判） |
| 跨厂商 Key | 文本 DeepSeek + 图百炼且没配 `IMAGE_API_KEY` 时，直接报"配了图接口地址但没配 Key"，**不会**把 DeepSeek Key 发到百炼 |
| 出站域名 | 仍限 https + 白名单（含 `*.aliyuncs.com`），`127.0.0.1`、内网域仍被拒 |
| 自检按钮 | 用户手动触发，一次 512 图 / 8 字语音，成本可忽略；不做自动探测，避免打开设置页就扣费 |
