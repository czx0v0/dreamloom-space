## 筑梦者 / Dreamloom（`D:/Coding/game/story_generation`）

LLM 驱动的多故事空间叙事引擎。从零搭建，当前处于 P1（纯逻辑核心）完成态。

### 已定的关键决策

- **形态**：React 18 + TS + Vite SPA + 极薄 Node 代理（单端口同源）；服务器**完全无状态**，存档在浏览器 IndexedDB（单库单 store `kv` + 前缀 key）。
- **密钥**：服务端 `.env`/`.env.local`（`LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL`）为主，浏览器 BYOK 作为覆盖项（只随请求头转发，不落盘不进日志）。首发目标 workbuddy.host；ModelScope Docker 创空间要求端口 7860、运行时注入 env、磁盘不持久（我们天然满足）。
- **不引入 LangChain/LangGraph**：编排是固定三步（narrate → audit → archive），框架会藏起 prompt、增加兼容性与 mock 成本。只借鉴"显式状态图"（`Scene.status`）与 checkpointer（行存储 + 快照）。
- **不用 Function Calling**（v1）：调用顺序固定，无选工具空间；自带兼容接口对 `tools`/`strict` 支持参差。用固定 JSON 契约 + `jsonrepair` + 严格校验。FC 留给入梦模式的 `DREAM_TOOLS`。
- **实体分层**：`Persona`（跨空间原型，全局）与 `CastMember`（空间实例）分离，导入是**深拷贝快照**；原型改动不影响实例，需要同步时走显式「从原型刷新」，只刷描述性字段。
- **三层故事线**：全局 `Scene.summary` 链 / 角色 `CastMember.arc[]` / 地点 `Place.events[]` / 伏笔 `Clue`（open↔resolved）。不做"摘要的摘要"（二次摘要会漂移且不可追溯）。
- **RAG**：浏览器侧（transformers.js + `bge-small-zh-v1.5`，512 维），以幕为块（>600 字按段落切、重叠 60 字），混合打分 `0.7*cosine + 0.2*recency + 0.1*entity`；`keyword` 实现作为零依赖兜底，模型失败自动降级。

### 关键规则（踩过的坑）

- **自动合并只认归一化后完全相等**。曾用"首字相同 + 编辑距离 ≤1"，会把「李雷/李雪」「王刚/王钢」判成同一人。相似名只提示、不合并（3 字以上才提示）。
- **`append-arc` / `append-place-event` 必须幂等**：patch 可能重放，不去重会重复追加经历。
- **关键词召回需要整串包含兜底**：中文 2-gram 分词对单字查询（如"信"）永远命中不了。
- 沙箱里 vitest threads 池会争抢临时目录（EPERM）导致部分测试文件被静默跳过 —— 已改为 `pool: 'forks'` + `fileParallelism: false`。

### 相似度用覆盖度而非 Jaccard（重要教训）
- Jaccard 在中文里方向是反的：

  「林昭在码头等他」/「林昭在仓库等他」Jaccard 0.56（实际两件事）
- 覆盖度（交集 ÷ 较小集合）：0.92 vs 0.71，才分得开。阈值 0.8。
- 取 max(1-gram 覆盖度, 2-gram 覆盖度)：1-gram 抓换语序，2-gram 抓连续短语。
- 补了"不能误伤"的测试固定这条边界。

## 追加（第十六轮：目标 / 阶段 / 结局 + 浮窗）

### 「一直推进没结束」的根因
- `mainGoal` 只是一句话：没有状态、没有达成判定、没有终点，所以故事默认无限延伸。
- 海龟汤的驱动力是"这件事能不能被解开"，不是"悬念多"。

### 三道闸
1. **目标**：`Objective { text, kind: main|side, status, atSceneId, origin }`，存 `SpaceMeta.objectives`。
   来源三种：建空间自动由 mainGoal 生成 1 条 main / 档案员 `add-objective` / 玩家在档案页手写。
   `mainGoal` 与第一条 main objective 用 `syncMainGoal()` 保持同步（两套真相是灾难）。
2. **阶段**：`resolvePhase()` 纯函数推导（不落库、不让模型判断，否则节奏漂移）。
   opening(<5 幕) / investigation(5–24) / climax(≥25) / ending(main done) / closed(endedAt)。
   每档对应一句 prompt 要求，climax 时"每幕必须朝主目标推进"。
3. **结局**：main 达成 → 出现「写结局」→ `finale: true` 走专用 prompt（不给选项、400–700 字、
   要收束所有线索并交代人物下场）→ 写完后 `endedAt` 落库 → 行动栏换成完结卡片（锁推进不锁数据）。

### 实现细节
- `applyPatch` 的 objectives 走 `ctx.objectives` 进、`outcome.objectives` 出；
  **没有目标类 op 时返回 undefined**，调用方就不必白写一次库。
- `achieve-objective` 用片段匹配（`text.includes(needle) || needle.includes(text) || 相似度≥0.6`），
  因为模型给的是"查清父亲死因"，而目标是"查清父亲十年前那夜是怎么死的"。
- 旧存档迁移：没有 objectives 时用 mainGoal 补一条，否则阶段永远停在 opening。

### 浮窗（P4.12）
- `ui/MentionPopover.tsx`：点正文人名/地名 → `session 内 createPortal` 出卡片，**不跳页**。
  角色卡显示身份/状态/想要/近况/关系；地点卡显示类型/一句话/特征/旧事。
  卡片里「看完整档案」才跳转。Esc / 点外部 / 滚动都关闭（滚动会错位，直接关比跟着跑省事）。
- 视觉区分：角色实线下划线，地点虚线下划线 + 略淡。

- 实测：真实模型对一段"去找老陈问清初七夜"的正文，正确输出了 add-objective / achieve-objective / move-to。

## 追加（第十七轮：空正文 bug / 模式 / 固定事件）

### bug：第 4 幕有选择没正文
- 根因：`advanceScene` 提交前**不校验 finalText 是否为空**。模型返回空（内容过滤/截断/流中断）时，
  `parseNarration('')` 得空正文 → `fallbackChoices` 补两条通用选项 → 仍然 `committed` 落库。
  **失败被伪装成成功**，比直接报错更糟。
- 修复：提交前 `finalText.replace(/\s/g,'').length < 30` → 抛 `E_EMPTY_NARRATION`、不落库、不推水位。
  30 字是保守门槛（模型偶尔返回「（继续）」这类占位文本）。
- 旧数据兜底：空正文幕显示「没写出内容」+ 跳时间线重写。
- 教训：`fallbackChoices` 是给"忘了写选项"的降级，不能用在"正文都没有"的场景。
- 连带的测试夹具问题：canonEdit.test 的 SCENE_TEXT 只有 26 字被拦，需加长到 30+。

### 空间模式（goal / free）
- `SpaceMeta.mode`，默认 goal。free 时 `resolvePhase` 固定返回 'free'：不催收线索、不给阶段要求、不推进度、不出现「写结局」。
- 实现取巧但干净：pack 里 free 模式把 `cluesSection` 的 staleAfter/pressureAt/maxOpen 全传 Infinity，
  不改签名、不影响现有测试。
- 模式可随时切换，不迁移数据。

### 固定事件（ScheduledEvent）
- `{ id, atSceneIndex, text, fired, origin }`。生成第 N 幕前把 `atSceneIndex===N && !fired` 写进 prompt 的「【本幕必须发生】」。

- seed 也会给 2–3 个节点（实测：第 5/8/12 幕各一个），建完仍可改。
